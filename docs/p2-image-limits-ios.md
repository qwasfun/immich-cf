# 官方 iOS：高像素原图 dev 真机验收

本轮客户端固定为官方 Immich **3.3.1 build 23**，保持 App 不修改。服务器填写 `https://immich-cf-api-dev.fun.workers.dev`，优先使用本轮独立 dev 验收账户，登录信息保存在 Git 忽略的本机 `work/dev-pixel-account.json`（不要提交或公开其中密码）；原 dev 测试账户已达到 20 张额度，仍可预览现有图片。测试时记录实际 iOS 版本、Wi-Fi/蜂窝网络和北京时间；客户端原有系统网络设置不必为本机探针代理而改变。

## 准备

1. 保留手机原件及独立备份；仅建立一个小型测试相册，不直接选择整个相册库。实验账户仍最多 20 张（含待恢复上传），先确认有剩余容量；遇到容量错误应记录，不为测试删除现有资产或手机原件。
2. 准备两三张有权用于测试的普通静态 JPEG/PNG：一张小图片、一张 4032×3024 或更大的手机 JPEG，以及可选大尺寸 PNG。成功项必须同时满足 **文件≤4 MiB、总像素≤64,000,000、宽高各≤16384**。保留原始 EXIF/XMP；是否被当前元数据安全规则支持须以实际结果记录。
3. 使用独立文件信息确认真实编码、字节大小与方向；不要仅凭扩展名或“高效/兼容”设置推断格式。不把 HEIC、Live Photo 的静态部分或有动态关联的导出文件当作普通静态成功项。像素上限放宽不改变 HEIC/视频/Live Photo 不支持范围。
4. 另准备一个≤4 MiB 的 Live Photo 原件，以及可选一张大于 4 MiB 的普通图片，用于失败隔离测试；不修改这些文件的元数据以绕过检查。只在小型测试相册中启用备份，失败后不要触发删除手机原件/释放空间操作。

本轮独立账户包含固定合成探针素材，其中带 large-header 标记的一项仅用于协议边界，并非可解码图片黄金样本，不用于真机画面验收。请按下面步骤新增你自己的普通静态照片，并只对指定照片记录显示结果。

## 成功上传、显示与重传

1. 确认 App 已连接 dev，登录后用户信息正常。
2. 先只选普通静态成功项，前台发起备份并等待本次队列结束。记录每项文件编码、尺寸、字节和上传结果；相同内容若已经备份，可表现为去重。
3. 刷新时间线，按照片实际拍摄日期寻找新图片（不一定出现在今天）；逐张打开预览，检查画面完整、清晰、方向和宽高比例正常。EXIF 方向 5～8 的横竖布局应正确，不应拉伸或镜像错误。
4. 再次发起备份/刷新，确认同一文件不增加重复图片；已有大图能重复打开。记录加载耗时、闪退、卡顿或白图，不能仅凭 Remote Sync completed 判断显示通过。
5. 使用此前已验证的“同步重置”入口执行一次重置，再刷新并打开这些图片。关闭重开 App，确认登录保持、图片齐全、无重复；重置是同步重建，不要求删除服务器资产或手机照片。

## 失败后恢复与重试观察

1. 在小型测试相册中加入 Live Photo 与一张尚未备份的普通静态 JPEG/PNG，前台启动备份。让 App 自行安排顺序，记录实际执行顺序；若 Live Photo 失败后尚有普通项，观察普通项是否继续上传。
2. 预期 Live Photo 仍被明确拒绝，不能将只上传静态部分视为完整备份成功；普通静态项应能独立上传、同步、预览。如果队列停止，记录现象，不能用公网探针“失败后继续”替代 App 调度验收。
3. 可再加入大于 4 MiB 的图片：预期返回 assetData 的 4 MiB 限制原因，不能显示为成功；同时观察普通项能否继续。若能准备超过 6400 万像素/单边 16384 且≤4 MiB 的独立样本，可另验证像素超限提示，否则记录“未测”。
4. 失败后分别观察当前轮、手动再启动备份一轮、重启 App 后再启动一轮：记录同一设备资产的失败次数、间隔、错误码和普通项进度。永久失败项是否反复重试仍属于官方客户端行为待验，不承诺本轮服务端改动会让它自动跳过。
5. 普通静态项上传期间可断网一次，再恢复网络并重新备份；确认最终可显示、无重复，并核对错误是否仅发生在断网时。间歇性网络故障单独记录，不能仅凭超时判定业务缺陷。
6. 取证后可从“测试备份相册/选择范围”移出失败项，保留手机原件，再确认普通项继续；不要把删除手机原件当作恢复办法。
