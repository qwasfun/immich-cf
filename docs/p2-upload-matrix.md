# P2 上传完整性与混合失败序列

日期：2026-10-15。对应 P2-01 内容校验、P2-04 失败序列及混合样本回归。CPU 超预算继续暂缓，G1 不提升为通过。官方 App、bcrypt cost 12、reset/ACK guard 与事务未更改。

## 本轮实现

PNG 在已有块长度、IHDR、IDAT、IEND 校验之外，逐块验证类型和数据的 CRC32。CRC 错误返回 400，字段为 assetData，提示重新导出原图。检查在校验和去重、上传意图预留和 R2 写入之前完成；损坏文件不会被当成成功备份。

算法依据 [W3C PNG 第三版 5.5 CRC](https://www.w3.org/TR/png-3/#5CRC-algorithm)。CRC 只能检测块校验错误，不证明像素流可解码，也不是密码学认证；本轮没有引入图像解码器、EXIF 旋转或格式转换。

## 已验证范围

- 本地真实 Worker/D1/R2：正常 PNG → 损坏 PNG → 超限文件 → 不支持格式头 → 正常 JPEG。正常图片继续成功；无失败资产或遗留上传意图；同步返回两张图片。
- 100 个合成变体（50 PNG、50 JPEG）：在两张既有图片中加入不同文本/注释，五个独立账户各 20 张。逐一验证上传 201、重复 200 且 ID 一致、原图字节相等、账户资产数及 Sync 数量均为 20。
- 合成 PNG 的 CRC 由 Node zlib 生成，服务端自行计算，避免直接复用服务端实现作为预期结果。
- 全套 `pnpm check` 47 项回归、格式、静态、类型与构建通过；契约校验 279 个操作、53 个来源通过。
- 公网验证脚本 `node scripts/upload-validation-probe.mjs` 仅上传应被拒绝的损坏/超限文件，验证字段错误及后续同步结束，使用临时会话后退出。

100 个变体只证明不同字节/校验和的存取与去重链路，不代表 100 张独立真实照片的方向、色彩、编码和解码覆盖。HEIC/视频头为合成拒绝用例，不算真实媒体试验。HTTP 请求按顺序成功不等于官方 App 的自动备份队列会跳过失败文件。
