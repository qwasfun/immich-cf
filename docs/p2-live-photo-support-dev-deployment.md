## 本机与公网证据

自动化覆盖照片 20,000,000 字节与 MOV 64 MiB 上限、超过旧 4 MiB 的照片、JPEG/HEIC/MOV 容器、字段错误、配对错误、越权、并发名额、断流及未完成 multipart 回收、去重与两份原件修复；同时覆盖额度耗尽、临时失败、缓存复用、跨月续跑、相册/回收/永久删除、双会话 Sync/reset/ACK 和 v1/v2 导出失败保护。

dev 公网完成 30 项 HTTP 检查，使用隔离测试账号，保存两组配对、共四份原件：

- 一组超过 4 MiB 的有效 JPEG 与合成 MOV，用于接口与尺寸验证；合成 MOV 不作为实际播放证据。
- 一组来自固定 Git 提交的公开真实 HEIC/MOV，保留完整字节和配对元数据，未修改或剥离元数据。
- 未配对照片与三种截断/非法 multipart 均返回 400，随后正常上传和重复上传成功。
- 视频 Range 返回 206，四份下载原件分别与上传前 SHA-1 一致，统计为两项逻辑资产。
- 原生 Images 生成两种 JPEG 并经实际鉴权路由读取成功；配对软删除、恢复、双会话 Sync 与 ACK 成功。
- 实际导出工具生成 v2 清单并取回四份原件，全部字节数/摘要验证通过，产生 `COMPLETE.json`。

公开样本出处与边界见[实现说明的验收部分](p2-live-photo-support.md#验收)。个人照片、会话和素材均未进入 Git；探针临时会话已退出，未新增运维授权。公开样本、接口 Range 和摘要成功不证明 iPhone 视频解码或保存到系统相册成功。

## 必须补充的 iPhone 验收

使用既有官方 iOS App 与 dev 地址，记录 iPhone 型号、iOS 版本、App 版本/build、每项结果和失败现象。各准备一组真实 JPEG＋MOV、HEIC＋MOV，保留手机上的原始照片用于比较。

1. 前台备份两组 Live Photo，确认服务端完成配对、每组只占一项，不能把静态部分上传成功算作整组成功。
2. 新拍两组，按日常使用方式进入后台，确认后台完成备份，再回到 App 检查是否仍有失败或缺失的动态部分。
3. 第二台设备登录同一账号，确认同步后看到照片、真实预览和动态效果；验证播放使用远端数据。
4. 在第二台 iPhone 下载/保存到系统相册，打开系统“照片”，确认两种格式都显示 Live Photo 且长按可播放；比较照片与动态内容，记录恢复结果。
5. 验证整组加入相册、回收、恢复，并检查另一设备同步收敛；异常时保留具体错误与时间以便查证。

上述结果全部确认后才能更新完整支持标记。本轮不替代整库灾备恢复验收，也不据此晋升 test/生产。
