# P2 重置快照 CPU 优化

日期：2026-10-14。官方 App、bcrypt cost 12、会话验证与 reset/ACK epoch 隔离不变。

## 定位与实现

代码路径检查发现两个可消除的工作量：显式 reset 仍读取不会使用的检查点；每条输出事件独立构造、绑定、序列化一条投递登记 SQL。这是可验证的开销来源，不是精确 CPU 火焰图归因；此前单次 16 ms 不能证明某一函数是瓶颈。

- `reset:true` 跳过检查点读取，增量仍只读一次。快照事务仍清除检查点并切换 epoch。
- 投递登记改为一次 `json_each` 批量 INSERT/UPSERT，只传事件类型和 ACK，不传图片内容。N 条事件由 N 条投递语句降为 1 条。
- guard 插入、清除游标/投递、epoch 切换、批量投递和 guard 删除仍在同一个 D1 batch 中。事务触发器与认证逻辑未改，没有跨请求缓存。
- 原有每用户 20 个小图片上限仍适用；本次不宣称无界图库性能或内存行为已验证。

## 回归与采样

真实 Worker 测试断言 reset 的检查点读取为 0、增量为 1，投递登记始终为 1 条；另新增连续五次非空快照、资产无重复/缺失、旧代 ACK 拒绝、本代 ACK 后空增量。原有部分 ACK、并发 reset/ACK、事务失败和恢复测试继续通过。

`scripts/budget-probe.ps1` 新增 `-SnapshotSamples 5`（最多 10），每次 reset 后 ACK，并比较图库资产集合、拒绝重复资产。可同时指定 `-IncrementalSamples 5`。统计工具分别输出 snapshot/incremental 的有效数、缺失数、最小值、中位数和 nearest-rank P95；不把网络耗时或缺失日志视为 CPU，不以少量样本证明总体 P95。

最终 `pnpm check` 全部 44 项测试通过，包含统计空样本、缺失、超预算与分位数计算。静态、类型、格式、构建、279 个 API 操作及 53 个来源的契约校验通过。本轮没有新增官方 iOS 真机验收。

## 发布与实测

代码提交 `06cb163`。Wrangler 因本机 TLS 连接重置未完成发布，改用 cloudflare-api 的内容更新接口发布已验证构建，保持现有配置和绑定。平台确认版本 `8e036342-096a-42a1-acc4-6d84996bc1bc` 承载 dev 100% 流量，发布记录 `6920bd6a-86b6-4cd4-8d81-ce3f24311802`。无数据库迁移，test/生产未更改。

此前版本基线因 TLS EOF 在四次快照后中断；失败运行不算完整通过。平台已取到其中三次 CPU 9/4/8 ms，一次缺失；见 [部分基线](contracts/p2-reset-before-cpu.json)。该失败运行的退出请求也失败，未确认临时会话已撤销，仍受原有会话有效期约束；没有为排查清除用户其它会话。

公网恢复后，2026-10-14 北京时间 22:28–22:29 完成 21 步验证：五次 reset 快照集合一致、无重复，每次 ACK 成功，随后五次增量均仅含 Complete，最后退出成功。登录成功/错误密码/未知账号的预期状态也通过。CPU 结果见 [发布后报告](contracts/p2-reset-after-cpu.json)。

最终取得 21 步中的 18 条 CPU 记录；健康检查、第 5 次快照、第 3 次增量未取得记录，保留 null。快照有效样本为 10/7/12/8 ms：中位数 9 ms、样本 P95 12 ms；增量有效样本范围 4–15 ms，中位数 7 ms、样本 P95 15 ms。每组仅 4 个有效样本，均有一次超过 10 ms，不能解释成总体性能分布。

CPU 统计仅依据平台 invocation 日志，不以启动耗时、D1 网络等待或 HTTP 总耗时替代。较少语句和跳过读取已由回归证明，但此前版本也有 4–9 ms 样本，不能只与历史 16 ms 单样本比较并宣称加速。当前仍有超预算样本，**Free CPU 门槛仍为 No-Go**；需要进一步分离鉴权、序列化、D1 绑定调用及冷/热实例开销，并扩大图库规模与采样覆盖。密码安全参数和并发隔离不作为降本手段。
