# P2 重置快照 CPU 优化

日期：2026-10-14。官方 App、bcrypt cost 12、会话验证与 reset/ACK epoch 隔离不变。

## 定位与实现

代码路径检查发现两个可消除的工作量：显式 reset 仍读取不会使用的检查点；每条输出事件独立构造、绑定、序列化一条投递登记 SQL。这是可验证的开销来源，不是精确 CPU 火焰图归因；此前单次 16 ms 不能证明某一函数是瓶颈。

- `reset:true` 跳过检查点读取，增量仍只读一次。快照事务仍清除检查点并切换 epoch。
- 投递登记改为一次 `json_each` 批量 INSERT/UPSERT，只传事件类型和 ACK，不传图片内容。N 条事件由 N 条投递语句降为 1 条。
- guard 插入、清除游标/投递、epoch 切换、批量投递和 guard 删除仍在同一个 D1 batch 中。事务触发器与认证逻辑未改，没有跨请求缓存。
- 原有每用户 20 个小图片上限仍适用；本次不宣称无界图库性能或内存行为已验证。

## 回归与采样

真实 Worker 测试断言 reset 的检查点读取为 0、增量为 1，投递登记始终为 1 条；另新增连续五次非空快照、资产无重复/缺失、旧代 ACK 拒绝、本代 ACK 后空增量。原有部分 ACK、并发 reset/ACK、事务失败和恢复测试继续通过。

`scripts/budget-probe.ps1` 新增 `-SnapshotSamples 5`（最多 10），每次 reset 后 ACK，并比较图库资产集合、拒绝重复资产。可同时指定 `-IncrementalSamples 5`。统计工具分别输出 snapshot/incremental 的有效数、缺失数、最小值、中位数和 nearest-rank P95；不把网络耗时或缺失日志视为 CPU，不以少量样本证明总体 P95。

本地全套原 43 项测试通过，随后新增采样统计测试单独通过（预算测试共 4 项）；总测试集合为 44 项。静态、类型、格式、构建、279 个 API 操作及 53 个来源的契约校验通过。本轮没有新增官方 iOS 真机验收。

## 发布与实测

待本轮发布后的平台记录补充。此前版本基线因 TLS EOF 在四次快照后中断；失败运行不算完整通过。平台已取到其中三次 CPU 9/4/8 ms，一次缺失；不能只与历史 16 ms 单样本比较并宣称加速。
