# Paid dev：永久删除任务定时续跑

2026-10-30。依据[Paid开发决策](paid-development-decision.md)，为dev恢复每5分钟一次的Cron。test/生产配置不变。保持活动触发与本人手动入口，三种入口使用同一持久任务和引用隔离机制。

## 行为

定时消费仅处理用户已明确永久删除、且到期的任务。每轮最多3项、每项最多2个对象；继续检查活动/其他退役/上传预约/其他复制预约引用。未获授权的原图与全部预约保留。账号退出、会话撤销或禁用不会撤销此前已提交的永久删除授权，因此定时清理无需客户端在线。

任务先隔离引用，再delete/head确认、标记完成；对象故障保留任务并设置5分钟后复查。已完成任务仍有界复查迟到字节。并发重入沿用不可逆隔离与状态CAS，重复删除安全。实验功能关闭时不消费。每轮日志只输出固定code、processed和completed计数；查询失败输出脱敏错误并抛出固定错误，让平台识别失败，不输出对象键、账号或原始异常。

这不启用回收站按天过期删除，不为未获永久授权的资产创建清理任务。CPU专项继续暂缓，批次上限继续保留；Paid不代替成本和容量验收。

## 验证边界

本机通过生产scheduled handler验证跨账号已授权任务、无会话/禁用账号、实验开关、数据库查询失败、R2删除失败后恢复、每轮3项上限和未到期任务保护；既有完整回归继续执行。测试维护路径仅存在于本机fixture，不进入线上Worker。

线上需分别记录Cron注册成功与真实scheduled执行成功。用之前已永久删除的合成资产任务验证：将其中一项标记queued/pending，账号保持禁用、无会话；等待平台定时消费，期间只通过Cloudflare控制面读D1，不调用客户端活动或手动恢复入口。检查任务与对象回到done，并比较原有资产、预约、相册、检查点、owner版本和同步时钟。

[Cloudflare说明](https://developers.cloudflare.com/workers/configuration/cron-triggers/)指出触发器变更传播最多可能需要15分钟；配置成功本身不算运行验证通过。套餐由用户确认，本轮账户API可读到default_usage_model=standard，不据此推断全部计费和资源上限。
