## 本轮实现

此前先写随机 R2 对象再插入 D1，数据库失败后重试会生成另一个随机对象。0006 新增 `upload_intents`：以用户和 checksum 唯一预约资产 ID、私有对象键和创建时间，预约提交后才写 R2。失败后保留预约；后续相同图片和并发请求复用 ID/对象键。完成时在同一 D1 batch 中插入资产并删除预约，资产提交前不会出现在 Sync。

依据 Cloudflare [D1 batch 官方文档](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)：批内顺序执行，任一语句失败则整个事务回滚。R2/D1 仍没有跨服务事务；预约将两者之间的失败转为可追踪、可重试状态。测试中的故障注入位于独立测试 Worker 入口，不包含在生产构建中。

| 故障位置                  | 留存状态                           | 同图重试                             |
| ------------------------- | ---------------------------------- | ------------------------------------ |
| R2 写入前失败             | D1 预约，无已发布资产              | 复用预约后写入                       |
| R2 写入成功但响应丢失     | 预约和同一 R2 键，无已发布资产     | 覆写同一文件，再发布                 |
| D1 资产插入或预约删除失败 | 整个 D1 batch 回滚，预约与 R2 保留 | 复用 ID，重新提交                    |
| D1 已提交但响应丢失       | 资产与 R2 存在，预约已删除         | 200 duplicate、相同 ID               |
| 并发同图上传              | 唯一预约、唯一资产、同一 R2 键     | 一次 201，其余 200                   |
| 已发布资产的 R2 对象缺失  | 读取 503                           | 再次上传同图可修复，ID/Sync 游标不变 |

存储异常返回 503，结构化错误定位 `assetData`，提示稍后重试同一图片。容量 409 明确说明包含待恢复上传。每账户已发布资产 + 待恢复预约最多 20，预约阶段原子执行容量约束，超限在写 R2 之前拒绝；已存在预约允许恢复。成功后预约删除，不重复计数。相同 checksum 的不同文件名/日期提交仍以首个成功发布的资产元数据为准。

预约不自动过期或删除：避免删除并发请求可能仍在使用的对象。未完成上传长期占用名额，用户需重试原图；人工清理须先停止该账户上传，核实资产引用与预约后操作。本轮没有开放清理接口、后台回收或批量备份。历史版本已产生的无主对象不能自动补建预约，仍待单独审计。发布交接期间若旧 Worker 的在途请求先提交了不同 ID，返回数据库实际 ID，并保留未使用预约供核对，不误删对象。

## 验证矩阵

本地真实 workerd + D1/R2，合成 PNG/JPEG，无用户真实照片。完整检查 19 项通过（包括原有 15 项）。

| 验证                        | 结果与证据边界                                                                     |
| --------------------------- | ---------------------------------------------------------------------------------- |
| R2 写前失败、写后返回失败   | 测试入口注入异常；重试后仅一个对象，预约清空                                       |
| D1 第二条语句失败           | SQLite 触发器阻止删除预约，验证资产插入同时回滚；连续失败和 Worker 重启后仍复用 ID |
| D1 提交后响应丢失           | 执行实际 batch 后注入异常；重试为同 ID duplicate                                   |
| 并发三次同图上传            | 一个 201、两个 200，同 ID，仅一份对象                                              |
| 已发布对象缺失              | 本地删除测试对象，读取 503；重复上传后字节一致且资产总数不变                       |
| 20 个预约容量               | 新图 409，无 R2 写入；旧预约恢复成功，变为 1 资产 + 19 预约                        |
| Sync 客户端停止读取且不 ACK | 取消响应读取，重新拉取仍返回未确认资产；不是公网物理断网测试                       |
| 部分 ACK / 非法 ACK 混合    | 非法输入整体拒绝，不推进资产；只确认前缀后重拉剩余资产                             |
| 正常 ACK 乱序并发和重放     | 已确认资产不回退、不重复返回；不包括 reset 并发                                    |
| 原有回归                    | 鉴权与隔离、UserV1 外键顺序、PNG/JPEG 上传、原图/预览字节、重启持久化继续通过      |

本次新增恢复行为尚未在官方 iOS 上人为断网验证；此前用户确认的上传、显示与预览成功仍有效，不扩大为断网恢复已通过。

## 部署与回退

先在 dev 应用 0006，再部署已检查的 Worker。0006 为增量表/触发器，不重写原资产、会话或检查点。旧 Worker 不能理解预约：发生回退时应先关闭上传实验入口并停止在途请求，保留新表和 R2 对象以核对恢复，不能在存在预约时让旧上传代码继续写入。不要通过删除数据库、重置手机或重传全部图库处理部署问题。
