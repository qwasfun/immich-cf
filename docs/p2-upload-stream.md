# P2 上传请求流中断与清理

2026-10-16，对应 P2-04 未知长度、网络中断与失败后重试。

## 改动

读取 multipart 请求体时出现流错误，现在返回 400 和 assetData 的明确提示：传输中断、文件未完整接收、恢复网络后重传同一图片。不会回显底层异常内容。若实际已超出 4 MiB + 64 KiB 请求上限，则保留 413，即使清理流时取消操作再次失败也不会覆盖原始错误。正常结束和异常路径均释放读取锁。

所有这些失败发生在表单解析、Live Photo 判定与上传预约之前，不发布资产、不写 R2 或产生上传意图。恢复网络后的新请求仍完整执行 Live Photo、格式、像素、校验和和配额校验。

## 测试与限制

本地测试入口注入部分字节后读取失败，以及未知长度超限且 cancel 抛错的请求。验证 400/413、assetData 错误路径、不回显异常、读取锁释放、D1/R2 无写入；随后同图上传和重复重试、Sync/ACK 成功。已有截断 multipart、大小边界、同步隔离和密码安全测试继续运行。测试故障入口不随生产代码部署。

公网复用混合 HTTP 队列探针验证正常上传、4 MiB 边界、超限和不支持格式拒绝、原图与 Sync/ACK。它不注入真实 TCP 断网，不能证明官方 iOS 的重试调度。实际连接已断开时，客户端也可能收不到服务器生成的错误响应。

仍采用有界请求体缓冲后解析 multipart，并非完整流式 multipart 写入；不扩大大小限制。CPU 超预算继续暂缓，App、密码安全及 reset/ACK 并发隔离不变。无数据库迁移，仅部署 dev，P2/G1 的真机混合队列与资源验收仍待完成。
