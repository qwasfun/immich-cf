# P2 EXIF 方向与布局尺寸

日期：2026-10-15。CPU 超预算继续暂缓；官方 App、密码算法、reset/ACK 并发隔离保持不变。

## 契约与实现

冻结的 [Immich v3.3.1 metadata.service.ts](https://raw.githubusercontent.com/immich-app/immich/v3.3.1/server/src/services/metadata.service.ts) 中 `isOrientationSidewards` 与资产宽高计算（193–199、341–343 行）将方向 5–8 的资产尺寸交换。仓库已冻结的移动端 `sync_stream.repository.dart` 将 AssetV2 的 width/height 写入远程资产记录。本轮对齐这一布局语义。

新上传 JPEG 从 APP1 的 Exif/TIFF 读取 IFD0 Orientation（0x0112）；PNG 从 eXIf 读取相同 TIFF 字段。支持 II/MM 字节序、SHORT/count=1、方向 1–8；缺少方向保留编码尺寸，5–8 交换宽高，1–4 不交换。尺寸仍经过原有像素/边长上限检查。

原图与预览继续返回同一份原始图片，保留 EXIF 和所有像素，SHA-1、去重与原图字节不变；服务端不旋转像素、不剥离方向、不生成规范化缩略图。实际显示依赖客户端图像解码器应用原图方向，不能仅由尺寸正确推导 iOS 镜像/旋转显示已通过。

解析仅遍历有界 IFD0，不追踪 GPS、MakerNote、子 IFD 或缩略图。头部/目录越界、截断、无效方向、错误类型/count、重复方向字段或重复 EXIF 块均明确返回 assetData 400；不在错误中回显原始元数据。异常发生在存储预约之前。

## 测试

`pnpm check` 全部 49 项测试及格式、静态、类型、构建通过。新矩阵覆盖 JPEG/PNG × 大小端 × 8 种方向（32 个变体），验证详情与普通/reset Sync 尺寸、重复 ID、原图及预览字节；原有 reset/ACK 故障并发矩阵继续通过。另覆盖截断、非法偏移/字节序/魔数、类型/count、方向 0/9、重复块拒绝与无上传意图残留。

测试夹具将标准 TIFF 方向嵌入既有图片，不是 32 张真实相机照片，也不是官方客户端显示测试。公网脚本 `node scripts/exif-probe.mjs` 在 dev 留下一张 `immich-cf-exif-6.png` 测试图，验证方向 6 的 320×240 编码尺寸变为 240×320 布局尺寸、原图/预览字节一致、Sync 与 ACK；重复运行复用同一文件。

## 历史数据与未验证项

没有迁移或静默回填历史资产，旧记录以及其重复上传继续保留原游标和已有尺寸；本轮只修正首次上传的新资产。历史尺寸修复需通过可靠的变更序号重新同步，作为后续独立工作，不直接更新数据库绕过同步协议。

iOS 3.3.1 build 23 仍需用带明显上下左右标记的真实照片验证方向 1–8（尤其镜像 2/4/5/7）、列表比例、大图预览和重启后的显示。方向 6 的合成测试图只能辅助检查，不能替代全矩阵。方向异常文件的 App 提示、PNG 解码器是否应用 eXIf、历史资产修复、完整 EXIF 信息同步均未完成。P2/G1 不因此整体通过。
