# Web 照片资料与时间修正

适用于照片、收藏和个人相册。回收站可读取已保存资料，恢复后才可编辑或从原件提取。资料与原件分别保存：修改描述、位置和图库拍摄时间不会重写图片、MOV 或文件摘要，不影响配对、收藏和相册关系。

## 使用

打开大图后点「详情」查看时间来源、拍摄时区、描述、相机、镜头、光圈、曝光时间、ISO、焦距和 GPS。已有照片首次打开资料时按需提取原件 EXIF；不批量扫描私人图库，也不自动覆盖已有拍摄时间。缺失字段显示未提供，部分无效字段显示读取说明。

点「编辑资料」修改描述（最多 2000 字符）与经纬度。位置必须成对填写；同时清空可移除图库中的位置，下载原件仍保留原有 EXIF。相机和镜头等拍摄参数只读。

勾选「修正拍摄时间」后填写当地时间与时区，或点「采用原件拍摄时间」带入原件值，再确认保存。支持 IANA 时区（如 `Asia/Shanghai`、`America/Los_Angeles`）和固定 UTC 偏移（`-14:00`～`+14:00`）。表单显示换算后的 UTC，保留毫秒。夏令时缺失时刻明确拒绝；重复时刻可选第一次或第二次，重新编辑时保持已有时刻对应的选项。

在选择栏点「修正拍摄时间」可批量处理 1～1000 张照片：

- 整体前移/后移：非零整数分钟，负数前移、正数后移，保留照片之间的时间间隔与各自拍摄时区。
- 设置相同拍摄时间：全部所选照片使用同一个当地时间、时区及重复时刻选项，原有间隔不保留。

保存后照片按新时间重新分组，年月数量与游标版本更新。定位先查当前范围内相同照片 ID；时间改变后仍可跟随该照片，移出当前筛选范围才使用时间最近的有效照片。相同时刻继续按 ID 稳定排序，可从前后方向继续浏览。

## 上传时间与原件提取

Web 新上传优先采用 EXIF `DateTimeOriginal`、毫秒和 `OffsetTimeOriginal`；原件没有偏移时按浏览器 IANA 时区解释，重复当地时刻默认第一次出现。无有效 EXIF 时间或无法解析的当地时刻回退到文件修改时间，并可在资料中修正。上传界面说明当前解释时区。

官方 App 上传仍尊重其提交的拍摄时间，同时记录可读取的照片资料。JPEG APP1、PNG eXIf、HEIC Exif item 复用既有有界容器读取；只读 TIFF IFD0、ExifIFD 与 GPSIFD 白名单，不追踪缩略图、任意子 IFD 或新的 MakerNote 结构。既有 Live Photo 识别与容器校验继续先执行。缺失或不支持的说明字段不被编造，也不扩大媒体格式范围。

原件来源信息和手动覆盖分别保存，重新提取不会覆盖手动描述、已移除的位置或修正后的图库时间。EXIF 导入不是完整 IPTC/XMP/私有厂商元数据支持，不生成 XMP 侧车。标准参考：[CIPA Exif/XMP 字段映射](https://cipa.jp/std/documents/e/DC-X010-2017.pdf)。

## 接口与一致性

| 接口                                                   | 行为                                                 |
| ------------------------------------------------------ | ---------------------------------------------------- |
| GET `/api/immich-cf/web/assets/{id}/metadata`          | 本人照片资料、来源字段、当前拍摄时间和图库版本       |
| POST `/api/immich-cf/web/assets/{id}/metadata/extract` | 同源请求，提交 `version`，有界读取原件并保存来源字段 |
| PATCH `/api/immich-cf/web/photo-metadata`              | 同源请求，提交 `ids/version` 及待修改字段            |

PATCH 可选字段：`description`、成对的 `latitude/longitude`（可同时为 null）、`dateTime/timeZone/occurrence`，或 `shiftMinutes`。`dateTime` 是无偏移的当地日期时间；`occurrence=earlier/later`，默认 earlier。指定 `timeZone` 而省略时间时只更新时区表示，保留实际时刻；相对偏移保留原有时区。两种时间修改方式互斥，未知字段、重复 ID 和超限明确拒绝。

所有写入在 D1 事务中再次核对会话、账号启用状态、图库版本和全部照片权限；任一项失败则整批不写。版本变化返回 409，需重新打开窗口核对后保存，不能盲目重复相对偏移。提交错误返回具体 `errors[].path/message`，不在错误或日志中回显描述、GPS、App 私有标识或令牌。

迁移 `0034_photo_details.sql` 为 assets 增加独立 `photo_metadata/local_date_time`，旧记录默认空值，不回填时间。资料变化更新业务时间、资产同步序号及图库版本。官方资产详情返回 EXIF 信息；`AssetExifV1`、`AlbumAssetExifCreateV1/UpdateV1` 沿用冻结 v3.3.1 字段、ACK 和读取守卫，`localDateTime` 按已知拍摄时区表示当地日期。App 的 opaque `mobile-app` 元数据保持独立。分批账号导出包含新增资料与当地时间；原件 ZIP 仍导出原始文件。

## 验证边界

本机测试覆盖大小端 EXIF、相机/GPS/毫秒、异常指针和循环、上海跨年与洛杉矶夏令时、三种图片容器上传、旧照片提取、描述/位置覆盖、批量间隔、1000 项修改及 1001 项拒绝、账号/会话/版本隔离、官方 EXIF Sync 和原件字节保持。完整检查共 268 项通过。

Chromium 验证资料展示/保存、原件时间带入、字段错误、时区预览、重复时刻回显、时间线重新分组和批量两种修正。1280×800、768×1024、390×844 验证操作区可见与无横向溢出。真实手机 Safari、官方 App 真机显示/播放及系统照片恢复需要独立验收。
