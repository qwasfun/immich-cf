# P2 上传表单字段边界

2026-10-16，对应需求 P2-01 字段与长度限制，兼顾 P2-04 失败后的重试恢复。

## 实现与兼容范围

修正 metadata 的 8 KiB 限制：此前按 JavaScript 字符数计算，多字节内容可超过声明的字节上限。现在按 UTF-8 字节检查所有文本字段，每项最多 8 KiB、合计最多 16 KiB；每请求最多 32 个字段，字段名非空、不含控制字符、最多 128 UTF-8 字节。重复字段用单次遍历检测，避免逐字段反复扫描表单。只有 assetData 允许文件，其他文件字段明确拒绝。未知的小文本字段仍接受并忽略，避免依赖严格字段白名单。

冻结的 v3.3.1 OpenAPI AssetMediaCreateDto 有 11 个字段，另保留官方移动端使用的 deviceId/deviceAssetId。32 项上限留有余量，但不代表兼容未来 App 的任意扩展。metadata 仍只接受一项 mobile-app 对象。错误定位具体字段；跨字段总量与数量约束使用“上传文本字段”或“上传表单”，给出单位、上限和修正方式，不回显提交值。空字段名可能由 workerd 在 multipart 解析阶段直接拒绝，此时返回 assetData 的重新选择图片提示。

Live Photo 已识别标记的持久登记在新增数量/文本/文件类型限制之前执行，防止动态请求携带超限附加文本后丢失既有防护。字段名与重复检查仍在登记之前。普通静态图片仍经过原有格式、XMP、EXIF、校验和及配额验证后才预约和写入；不会因为同图已存在就跳过字段检查。

## 回归与公网复验

本地真实 Worker/D1/R2 回归验证：8 KiB 加 1 字节的多字节 metadata、被忽略文本超限、文本合计超限、超过 32 项、附加文件、文本字段冒充文件、超长/空名称均拒绝，且资产、上传意图和 R2 无残留。正好 32 项、16 KiB 文本、8 KiB metadata、128 字节字段名的请求成功；同图重试 ID 相同，Sync 的 metadata 原值保留，ACK 成功。另验证动态标记与超量文本组合后静态重试仍拒绝，而其他普通静态图可继续上传。

公网脚本：`node scripts/upload-fields-probe.mjs`。仅面向 dev，复用已确认的本机代理 `http://127.0.0.1:7890`、curl TLS 1.2、相同内容上传恢复和强 ETag 分段读取；证书校验保持开启。拒绝样本不增加资产，正常样本复用既有 small.png，重复执行去重。报告只保存脱敏状态与传输指标，不保存密码、令牌、原始响应或照片元数据。另复跑完整混合大小探针确认接近 4 MiB 路径。

## 剩余限制

本轮本地验收：`pnpm check` 的格式、lint、类型、78 项回归和 dry-run 构建全部通过，无失败或跳过；冻结契约 279 个操作/53 个来源通过。构建 165.06 KiB，gzip 41.32 KiB。公网发布结果另行补充，不以本地构建替代发布证据。

仍先读取最多 4 MiB + 64 KiB 请求体，再由 workerd 解析表单，以上字段限制发生在解析后；没有实现流式 multipart，也不能据此声称降低了解析阶段的 CPU 或峰值内存。无数据库迁移。官方 App 不修改，bcrypt cost 12 与 reset/ACK epoch/事务隔离保持原状。CPU 超预算继续暂缓，G1、真实图库及官方 iOS 混合队列/失败重试仍未验收。
