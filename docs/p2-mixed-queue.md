# P2 混合大小与不支持格式恢复矩阵

日期：2026-10-15。本轮补齐测试、在线验证脚本和验收记录，不修改服务器上传策略、官方 App、密码校验或 reset/ACK 隔离；CPU 超预算继续暂缓。

## 服务端测试

本地真实 Worker/D1/R2 顺序发送：小 PNG → 超限 PNG → HEIC/MP4 签名 → Live Photo 关联字段 → sidecar → hidden 动态部分 → 上限减 1 字节 PNG → 恰好上限 PNG → 小 JPEG。上限为 2 MiB，三个边界样本均为带有效 CRC 的完整合成 PNG，超限样本仅超过 1 字节。

上传使用无 Content-Length 的 16 KiB 分块流；失败项返回预期 400/413，并断言结构化错误定位具体字段。每个失败项重复提交，再并发提交全部失败项。另以截断 multipart 模拟不完整传输，确认 400 后可重新提交。截断 EOF 不等价于实际手机断网或进程被杀。

最终仅四份正常逻辑资产，上传意图为零，R2 对象数为四；逐份原图字节完全一致。Sync 只返回四份正常资产，ACK 后增量只有 Complete。既有成功响应丢失、R2/D1 故障和 reset/ACK 测试继续运行。

HEIC/MP4 使用合成容器签名，不是可播放/解码的真实媒体。Live Photo 用例覆盖显式关联字段、hidden 上传和 sidecar，不证明可以识别任意缺少标记的静态部分。

## 官方 3.3.1 队列源码观察

依据已冻结本地源码 `mobile/lib/repositories/upload.repository.dart` 与 `mobile/lib/services/foreground_upload.service.dart`：非 200/201 返回失败；413 被客户端替换为固定英文“文件过大”错误，服务端详细中文不一定展示。传输异常有一次重发；前台循环会处理后续项目，但取消、配额错误及后台调度仍有其他分支。源码观察不作为真机通过记录。

**Live Photo 部分备份风险仍未解决。** 前台路径先上传动态部分，只有成功才填入 livePhotoVideoId；动态部分失败后仍可能继续上传无关联字段的静态图片。服务端现有格式/字段拒绝不能保证该静态请求被识别为 Live Photo，也不能保证 App 不把它计为成功。本轮不伪造“完整 Live Photo 备份”支持；真机备份测试应排除 Live Photo，完整风险需要另行处理。后台路径的行为不可由前台代码推断。
