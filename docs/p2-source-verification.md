# P2 历史原图只读完整校验

上轮 HEAD 对账已覆盖当前资产、历史原图和预约，但无原生 SHA-1 的旧原图只能按存在性和大小分类，无法识别等长内容变更。本轮复用现有升级接口，增加手动只读完整校验，不修改官方 App，不改变媒体读取或恢复操作的默认行为。

## 接口与边界

`POST /api/immich-cf/upgrade-integrity` 提交 `{ "id": "资产 ID", "verifySource": true }`。apply 必须省略或为 false；同时传 apply=true 返回 400，错误定位 apply 并说明 verifySource 为只读模式。verifySource 必须为布尔值，类型错误定位对应字段。未知字段继续拒绝，不回显提交值。

接口复用现有会话认证与账户隔离，只读取该资产持久化的 integrity_source_key。缺少独立历史源引用、源路径等于当前路径、缺失、大小不符或摘要不符均为 409。每次一张、最多 4 MiB，验证真实读取长度，并完整计算 SHA-1 与既有 D1 checksum 比对。GET/读取故障返回可定位 id 的 503，可重试同一资产。

成功返回 target=source、sourceBytesVerified=true、bytes、applied=false、observationOnly=true、snapshotConsistent=false。不设置原生摘要，不更新数据库、不覆盖源、不写校验副本、不删除预约、不推进资产或 Sync 游标。当前副本即使缺失，也只核对源，不触发恢复；恢复仍须另行使用既有预检/apply 流程。

普通升级与恢复复用相同的有界完整读取和 SHA-1 比对逻辑。verifySource 省略或为 false 时保持已有行为；当前副本已验证的快速返回不能替代 verifySource 对历史原图的完整读取。

## 观察含义

sourceBytesVerified 表示读取到的该版完整原图与查询时的资产记录相符，不是跨 D1/R2 的一致性快照，也不是持续健康承诺。并发修改仍需重新核对。HEAD 对账中的 checksum-unavailable 依旧正确：手动重算通过并不会给旧对象添加原生 SHA-1，二者不能互相冒充。

校验不包含完整图片解码、色彩或方向的真机验收，不作为 100 张真实照片验收的替代。CPU 超预算继续暂缓，不因每张限制为 4 MiB 就宣称 Free/G1 资源关口已通过。

## 工具与测试

`node scripts/storage-audit-probe.mjs --verify-sources` 先按原有游标分页发现历史源，再顺序完整校验。省略参数仍只做 HEAD 对账。照片内容始终在 Worker/R2 内处理，不由该探针下载到本机；报告过滤 ID、路径和摘要，只保留逐项大小、校验状态、时间及传输指标。任一失败都会设置 complete=false，保留已完成项，退出时清理临时会话。

复用已验证的 curl HTTP/1.1、TLS 1.2、证书校验和 127.0.0.1:7890 代理。每个只读请求最多 3 次、每次 20 秒、总预算 60 秒，分页最多 10 页；不重试字段错误、401、409 或证书错误。登录不自动重试。间歇性网络波动按有界路径记录，不单独归因于业务缺陷。

回归覆盖：无原生摘要源的等长损坏识别；成功和失败均不改数据库、R2 对象或同步；源存在且副本缺失时不偷偷修复；源缺失、大小错误、读取不可用及重试恢复；字段、多字段约束、认证和账户边界；缺少或自引用源路径；4 MiB 边界和超限拒绝。完整套件继续执行密码、Live Photo、原有升级恢复和 reset/ACK 并发隔离。

Go：手动只读完整核对、按既有流程决定是否需要恢复。No-Go：隐式写入原生摘要、把一次快照证明当成永久备份完整性、自动删除或降级密码/媒体摘要/同步隔离约束。

本轮本机验收：`pnpm check` 107 项回归通过，无失败或跳过，格式/lint/类型和 dry-run 构建通过。冻结契约保持 279 个操作、53 个来源。构建 203.29 KiB / gzip 50.17 KiB；没有数据库迁移，认证和 reset/ACK 实现未修改。
