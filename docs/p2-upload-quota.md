# P2 上传名额与保留预约的去重计数

2026-10-17，对应 P2-02 配额预留与失败恢复、P2-04 重试/并发。

## 问题与修复

上传已预留 intent 后，另一个在途发布者可能以相同 owner/checksum、不同资产 ID 完成发布。当前 Worker 按唯一约束返回真正已发布的 ID，并保留未使用的预约和对象引用供后续对账。原触发器简单相加 assets 与 upload_intents，将这份已成功发布的逻辑图片计了两次。例如 19 张资产加 1 份同图旧预约，就会提前拒绝第 20 张图。

迁移 0012 只替换 upload_intents_limit：名额为“当前账户资产数 + 当前账户尚无对应已发布资产的预约数”。关联查询同时匹配 owner_id 和 checksum，其他账户的同哈希资产不能抵扣本账户的未完成预约。20 张实验上限、现有预约可恢复、已存在资产可去重的语义继续有效。判断仍在 INSERT 触发器内，与预约插入同一数据库写操作，避免两个上传都读取到最后一个名额后同时通过。

这是实验账户的逻辑资产名额，不是 Cloudflare R2 物理存储配额。冗余预约和未引用对象继续保留；此修复释放的是重复计数，不代表已回收存储。保留引用可避免遗失恢复线索，也避免与仍可能写入同一键的在途请求发生删除竞态。自动对账/清理仍需独立设计与验收。此迁移不改变资产、预约、同步时钟或原图内容。

## 回归矩阵

- 非空 SQLite 迁移：先运行原触发器，复现 19 张资产和 2 份已发布同图预约时错误拒绝新名额；应用 0012 后，原表和同步时钟快照完全相同，最后一个名额可预留，后续新图仍拒绝。另一账户同哈希资产不会令本账户未完成预约免费，其他账户的名额独立。
- 实际本地 Wrangler/Worker/D1/R2：故障入口在预约和 R2 写入后模拟另一个发布者以不同 ID 发布，验证返回 canonical ID、旧预约及两个对象均保留。再上传 18 张有效 PNG 合成变体，资产共 19 张，仍可预留最后一张 JPEG。
- 最后一张 JPEG 在 R2 写入前故障：503，预约保留并占用最后名额；另一张不同图片 409、定位 assetData，拒绝发生在 R2 写入前。恢复 JPEG 后 201/200 去重，资产共 20 张，冗余预约保持，既有资产与原图不变。Sync 返回恰好 20 个唯一资产 ID，不包含旧预约 ID，ACK 成功。
- 独立账户 19 张有效 PNG 合成变体后并发上传两张不同图：仅一张 201，另一张 409；最终 20 张资产、无待恢复预约、20 个 R2 对象。
- 全套密码、Live Photo、增量 multipart、原图校验及 reset/ACK 并发隔离回归继续执行。上述变体不冒充独立真实照片或真实旧 Worker 差分验收；模拟发布交错只存在于本地测试入口。

## 发布与验收边界

本轮本机开发与 dev 发布；通过 release 脚本应用 0012 并部署。公网复用 `node scripts/bulk-recovery-probe.mjs` 和 `node scripts/mixed-queue-probe.mjs --curl --tls12 --recover --proxy http://127.0.0.1:7890`。原图数据请求使用已验证的代理、TLS 1.2、curl 有界上传/分段恢复；上传单次最多 60 秒、总计 120 秒、最多三次，保留证书验证。小 JSON 网络失败最多整轮复验一次，保留失败报告。

公网正常链路用于验证发布后无回归，配额边界和交错故障只在隔离的本地账户中验证。公网不填满、清理或修改真实用户的预约/对象来制造边界。官方 App、密码 KDF 和 reset/ACK 协议与事务保持原状，CPU 超预算继续暂缓；未据此宣称 Free/G1 或 iOS 混合队列验收通过，test/生产不在本轮发布范围。

回退 Worker 时保留 0012；本轮运行逻辑依赖数据库触发器，回退 JS 不能恢复旧计数。若需回退触发器，应先停止该环境上传并确认多计名额的影响，保留所有资产、预约和对象供核对。

本轮 `pnpm check` 格式、lint、类型、88 项回归及 dry-run 构建通过，无失败或跳过；冻结契约 279 操作/53 来源一致。实际本地 Wrangler 迁移与 Worker/D1/R2 回归通过，非空迁移快照在 SQLite 中验证。构建仍为 194.15 KiB，gzip 48.27 KiB。本轮行为修复在数据库触发器中，Worker 仅补充解释性注释。
