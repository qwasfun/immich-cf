# P1 JSONL 分块传输与中断恢复

日期：2026-10-14；冻结官方 Immich v3.3.1，官方 App 不修改。此增量对应需求 P1-04 的流式编码和中途断线矩阵，不扩展资产功能。

## 实现

`sync-lines.ts` 替代在 start 中一次性编码并排队全部事件的实现。响应按读取需求编码事件，每次 enqueue 最多 16 KiB，取消读取时释放剩余事件引用及编码缓冲。每条 JSON 记录仍以 LF 换行结尾，Content-Type 保持 `application/jsonlines+json`；事件顺序、内容和 ACK 不变。数据库读取和投递登记仍在响应之前完成，取消响应不自动推进检查点。

依据 [Cloudflare Workers Streams 文档](https://developers.cloudflare.com/workers/runtime-apis/streams/)（2026-10-14 核实），响应可通过 ReadableStream 输出。这里限制的是应用每次 enqueue 的大小，不是网络包或客户端收到的 chunk 大小：Cloudflare、HTTP 和网络仍可合并或拆分。当前仍一次查询最多 20 张图片的有界事件集合，单条事件编码仍需要自己的缓冲，不声称实现大图库分页或恒定总内存。

## 冻结客户端依据与重要边界

已读取冻结提交 `db6e11ecc851228aec9c525abb0ee026d1f5055e` 的 [SyncApiRepository](https://github.com/immich-app/immich/blob/db6e11ecc851228aec9c525abb0ee026d1f5055e/mobile/lib/infrastructure/repositories/sync_api.repository.dart)：先流式 UTF-8 解码，再按换行拆分并保存尾段；EOF 时未闭合的尾段不解析。SyncStreamService 应用一组同类型事件后确认最后一个 ACK。

测试辅助解析器是按上述逻辑写的 JavaScript framing 模型，只验证 UTF-8/换行处理，不是运行官方 Dart、DTO 转换器或参考服务器，也不等于 P1-05 差异测试。单元夹具的简化字段只用于编码测试；真实 Worker 集成用例额外校验资产 DTO。

源码中的 `Remote Sync completed` 日志在读取结束后输出，本身并没有证明收到 Complete 事件。因此验收工具对普通数据流单独检查最后一条 `SyncCompleteV1`，不能只看 HTTP 200 或此日志。reset 是独立控制流，不要求 Complete；不能把缺失 Complete 的普通流当作 reset。此前真机通过结论仍依据用户操作结果及日志综合判断，不撤销既有反馈，也不扩大其覆盖范围。

## 验证矩阵

完整检查 30 项（原有 25 项 + 本轮 5 项）。

| 场景                       | 验证方法与期望                                                                                                                |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 中文、emoji 跨分块         | 在合成响应的每个字节位置分割、逐字节投递、多行合并；数据及 ACK 完全一致                                                       |
| 字段空值、文件名换行       | null 保留，文件名换行被 JSON 转义，不产生额外记录                                                                             |
| 末行换行 / 半行 EOF        | 完整末行可解析；去掉末尾 LF 后 Complete 不被解析，完成判定为 false                                                            |
| 缺少 Complete              | 合法记录结束但无完成事件也不判定完成                                                                                          |
| UTF-8 / JSON 损坏          | 严格解码报错，不产生伪成功                                                                                                    |
| 背压与取消                 | 不读取时不编码；读取首块后取消，不编码后续事件                                                                                |
| 超过 16 KiB 的单行         | 多次输出，跨块重组正确且每次输出不超过 16 KiB                                                                                 |
| 空图库 / reset             | 空图库仅 Complete 可完成；reset 控制事件正确解析                                                                              |
| 编码异常                   | 响应读取失败，不伪造完成标记                                                                                                  |
| 真实 Worker 半行中断与 ACK | 上传两张合成图片，真实 JSONL 重分块；完整应用第一张后仅 ACK 完整前缀，第二张半行不确认，重连只返回剩余资产，最终 ACK 后无重复 |

本地“半行中断”是在真实响应字节上截断模拟，配合真实服务端 ACK/重连；不是 iOS/公网物理中断抓包。取消背压单元测试在 Node Web Streams 执行，真实 workerd 集成验证响应可完整消费与同步状态。用户先前确认的离线恢复通过仍有效，但本轮改动后的真机复测、真实代理分块、Free CPU 测量及 P1-05 参考差异仍待完成。
