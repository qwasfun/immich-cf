# P2 R2 原图校验与等长异常恢复

2026-10-16，对应 P2-02 写入确认、P2-03 原图校验与 P2-04 幂等恢复。继续 dev 本机开发，CPU 超预算暂缓。

## 实现

此前预检查和媒体读取只比较 R2 对象大小，等长替换可能被误认为有效原图。现在复用上传时已计算的 SHA-1，将二进制摘要传给 R2 put 的 sha1 选项；发布 D1 资产前，检查返回对象大小及原生 checksums.sha1 与资产一致。缺失或错误时返回 assetData 的 503 重试提示，保留上传预约，不发布资产。没有增加 Worker 全图哈希次数。

API 根据 [Cloudflare Workers R2 文档](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/#checksums) 实现：指定校验和用于接收内容完整性检查，原生摘要可从 checksums 读取；不把 ETag 或自定义元数据当作 SHA-1。SHA-1 沿用冻结 Immich 的资产去重契约，不用于密码存储或授权，也不把它宣传为抵御恶意哈希碰撞的方案。

新增迁移 0011 的 assets.r2_sha1_verified 默认为 0，保留既有资产的读取行为。新资产为 1，预检查必须核对原生 SHA-1，缺失/不匹配则允许重传；媒体 GET/HEAD/Range/条件请求在返回图片或 304 前同样核对，不通过返回 503/no-store。head/get 边界仍用强 ETag 条件读取，get 返回对象也检查原生校验。

同图重传对没有原生校验的旧对象或异常对象，以此次完整验证的文件写回相同私有键并携带 SHA-1；确认写入后才将标记置为 1。标记更新失败返回 503，可用同图重试恢复。升级不改资产 ID、元数据、名额或 sync_seq，不触发额外资产事件；一旦升级，不会因为原生校验丢失而退回旧的大小判断。迁移不扫描、下载或重写私人照片，不要求全库重传。旧资产尚未升级且没有原生校验时仍只有大小保证，这一缺口仍公开保留。

旧对象显式升级会增加一次 R2 put 和 D1 标记更新；升级完成且原生校验一致的重复请求仍只检查对象，不反复重写。不据此声称免费额度或 CPU 关口已通过。

## 回归

- 真实本地 Worker/D1/R2：新写入的原生 SHA-1 与 fixture 的 Node crypto 摘要一致。
- 等长错误内容带其真实 SHA-1、等长对象缺失 SHA-1：预检查允许恢复，原图/预览/Range/HEAD/304 均拒绝；跨用户仍 404。并发同图重试恢复到相同 ID，仅一个对象，数据库行和同步版本不变。
- head 后、get 前等长替换：条件读取拒绝，重传恢复。
- 注入错误 put 校验和、移除 put 校验选项：拒绝发布，预约保留；下一次恢复发布同一预约 ID，重复不增加资产。
- 非空迁移：旧资产仅增加默认 0 标记，原字段保持；升级标记不推进同步时钟，非法标记受 CHECK 约束。
- 旧对象兼容、升级 D1 失败及重试、升级后原生校验丢失拒绝；原有 Live Photo、字段边界、密码、reset/ACK 回归继续执行。
