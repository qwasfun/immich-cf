# P2 逐项推进与退出验收

日期：2026-10-18。本轮范围为 **dev 分支本机开发，不部署、不访问远程图库**。以完整需求第 11.4 节为基线，并执行用户后续确认的 4 MiB、6400 万像素/单边 16384、官方 App 不修改、Live Photo 防护、bcrypt cost 12、reset/ACK 并发隔离约束。

**P2 当前未全部验收完成，G1 保持 No-Go。** 用户本轮明确回复高像素/混合队列尚未真机测试；CPU 超预算仍按既有要求暂缓，不通过扩大功能、降低密码安全参数或跳过验收来绕过关口。

## 本轮私人语料实跑

当前目录 124 个不同内容：101 JPEG、23 PNG。独立 Windows System.Drawing 读取布局、EXIF 方向，并生成临时缩放图、读取角点以抽查解码；全部满足当前字节与像素范围。此抽查不等于逐像素/色彩、方向人工审阅或 iOS 验收。

第一次以“全部普通静态”假设运行，在首项遇到明确 Live Photo 配对元数据 400，完整验收失败。没有抹去该结果；首次报告保留 work/p2-readiness-initial-report.json。之后用当前生产 imageHeader 做兼容性分类，识别到 100 个 JPEG 带配对标记，剩余 24 项布局与独立期望一致。分类来自当前实现，不是独立 HEIF/Live Photo 源真实性证明；没有通过剥除元数据或把初次失败改称成功来凑数。

另建忽略目录内 manifest-p2-mixed.json，100 项预期 400、24 项预期 201。完整隔离本机 Worker/D1/R2 七批实跑 complete=true：100 项均拒绝且不进入资产集，24 项上传、立即重传同 ID、原图/当前预览逐字节、实际 MIME、独立布局、Sync/ACK、空增量及退出通过。账户每批最多 20 项，不改变正式额度，不读取 dev 登录凭据，不上传公网，不删除/转码任何原件。

成功内容仍只有 **24**，因此声明真实成功内容门槛仍为 false；至少还缺 **76** 份符合当前支持范围的不同成功内容，拍摄来源也需人工复核。同次拍摄的缩放/转码版本不能重复计入拍摄数。[本轮脱敏汇总](contracts/p2-private-mixed-readiness.json)仅含统计，不含原文件名、路径、内容摘要、标识值或凭据。

## 特殊格式验收工具

原工具清单仅支持 JPEG/PNG MIME，无法如实填写 HEIC、MOV。现在清单增加 image/heic、image/heif、video/quicktime、video/mp4，但**只能 expected.status=400/413**，不能标 201 或计入成功真实内容。匿名文件名扩展与 MIME 一致；成功项仍只允许 JPEG/PNG。

[特殊格式清单示例](templates/p2-rejected-formats-manifest.example.json)是占位模板，示例文件不存在，尺寸须按实际普通静态项独立确认。请把非唯一副本放在 tests/private-fixtures 下的独立目录并复制模板到该目录；配对项使用相同 captureId，不能填私密标识。每文件最多 8 MiB、全批最多 1 GiB/200 项，业务上传仍最多 4 MiB；更大的视频不能依靠截断后充当原件。清单和样本都保持 Git 忽略。

```powershell
pnpm p2:real-media --manifest tests/private-fixtures/special-media/manifest.json
```

新增集成用例：PNG 成功 → HEIC/HEIF/MOV/MP4 容器拒绝 → 带配对标记 JPEG 拒绝 → JPEG 成功，验证两份成功资产、无拒绝项预约/对象、Sync/ACK 与空增量。容器样本为合成品牌/结构探针，并非真实可解码 HEIC 或视频；不能据此补写真实格式验收。

## 大文件边界的基线对齐

原始 P2-05 曾列 20 MiB 负载，但用户后续把支持上限定为 4 MiB。当前 20 MiB 只属于拒绝范围：已知长度直接在读正文前返回 assetData 413（流只可能预取前缀），未知长度在读至当前请求上限后 413、取消后续流并释放锁。新增测试以固定块流模拟总量 20 MiB，不需要把整个大文件缓存/发送到公网；两种情况均检查无资产/预约/对象变化，随后普通上传和 Sync 恢复。此结果不是平台 CPU、内存测量，也不改变暂停决定。

## 剩余步骤与 Go/No-Go

1. 本机自动化与特殊格式工具继续保持回归，无需修改官方客户端。
2. 补足至少 100 个合规混合成功内容并独立复核来源、方向和画面；当前已提供的配对标记文件保留作拒绝用例，不能去标记后冒充普通源件。
3. 按[官方 iOS 测试步骤](p2-image-limits-ios.md)填写真机记录。用户本轮回复“尚未测试”，本机工作继续，真机项保持待验。
4. 准备真实 HEIC/HEIF、小视频和完整 Live Photo 配对副本，确认拒绝提示与队列行为；是否实现 HEIC 转换需另做方案和真实样本验证，目前仍拒绝。
5. CPU 项恢复后完成实际 Free 平台资源/成本验证，再决定 G1。当前不创建付费资源、不擅自恢复预算工作、不进入 P3/P4 扩张。

目前决策：继续已授权本机开发与有限验证；**P2/G1 不通过、不得宣布全部完成**。剩余证据不是测试代码能替代的：真机记录、合规真实成功语料、实际特殊媒体和被暂停的平台预算。
