# Web 照片归档管理

## 使用方式

- 在照片大图中点击“归档照片”，已归档照片显示“取消归档”。
- 在照片、收藏或相册中选择 1～1000 张照片，使用“归档所选”或“取消归档”。整批成功后清空选择；失败保留照片和选择，不自动重发操作。
- 侧栏“归档”显示本人未删除的归档照片，支持文件名、日期、类型筛选、升降序、按天/Shift 选择、年月定位、自动补页、刷新与返回位置恢复，以及原有大图和下载功能。
- 归档照片移出默认主时间线；主照片页的文件名搜索仍覆盖归档照片，并显示“归档”标记。相册选图使用完整图库，可选择归档照片。

归档是可逆的整理状态。收藏、相册关系、封面和已有分享继续保留，分享访客仍可查看已授权照片；归档不会撤销分享。取消归档后按原拍摄时间返回主时间线，不重新上传或占用新名额。此定位与[官方归档说明](https://docs.immich.app/FAQ/#how-can-i-hide-a-photo-or-video-from-the-timeline)一致：从主时间线收起，仍可搜索并集中查看。

归档照片仍可编辑资料、加入/复制/移动相册、分享和下载。Live Photo 只对照片主体设置归档，隐藏 MOV、配对关系和两份原件保持。删除归档照片后，它出现在回收站；恢复后仍为归档状态，需单独取消归档才返回默认主时间线。

## 提交与一致性

新增同源 `PATCH /api/immich-cf/web/archive`，JSON 字段为 `ids`、布尔 `archived` 和照片列表 `version`。成功返回 `processed/changed/unchanged`，重复设置同一状态不会产生新的同步版本。

服务端在同一 D1 事务内重新校验有效会话、启用账号、全部照片归属、未删除/可归档范围与图库版本。任一照片不可操作时整批拒绝；中途数据库故障整体回滚。字段错误返回具体字段路径与修正要求，不回显提交值。409 要求刷新核对后再操作，503 提示先核对结果，不自动重发。

照片列表支持 `view=archive`；`view=library` 表示未删除的完整照片图库，供相册选图使用。收藏和相册保留归档照片；回收站同时显示归档与非归档照片。两种新视图复用账号/范围/筛选/版本绑定的双向游标和年月接口，不能混用游标。

迁移 `0036_photo_archive.sql` 新增独立归档列、索引和临时事务守卫，不修改原有 Live Photo 物理可见性。归档变化推进资产同步版本、更新时间与账号修订；官方详情返回 `isArchived` 和冻结枚举 `visibility=archive/timeline`，初始/增量及相册资产 Sync 同步该状态。官方单张/批量资产更新支持冻结的 `visibility` 字段，同时更新收藏时也在同一事务内提交；隐藏/锁定仍未开放。官方统计支持归档可见性筛选。

账号分批导出和旧版清单保留新增 `archived` 字段；原件字节、摘要、拍摄时间、App 私有元数据、相册关系和逻辑用量保持。自动化与真实设备验收分别记录，服务端 Sync 检查不能替代官方 App 真机验证。
