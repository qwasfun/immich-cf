# P2 上传超时分阶段诊断

日期：2026-10-16。承接上一轮接近 4 MiB 正常图片公网超时。本轮只增加诊断工具与测试，不修改 Worker、认证、reset/ACK 或上传限制；dev 保持版本 e88a4007-2d59-4748-94d3-df43143bfa69，不重复部署相同运行代码。

## 工具与回归

`node scripts/upload-transport-probe.mjs` 使用固定 dev 地址、忽略目录中的账户文件及四个固定合成样本，最多创建既有探针相同的逻辑图片，不删除数据。它使用 Node HTTPS 独立连接和明确 Content-Length，记录 TCP/TLS、本机请求写出、响应头、正文长度、总耗时、状态码和限定网络错误码。每项等待最多 45 秒，每项完成即保存到 work/upload-transport-probe.json；即使前项失败仍检查后续项，最后尝试退出会话并记录是否确认。

报告不保存令牌、账户、图片、请求头、响应正文或异常消息。响应读取上限为 64 KiB；单次失败不会无限重试。共享测量器有本地 HTTP 回归，覆盖成功、413、超时、正文截断、响应上限与脱敏。

**requestFinishedMs 只是本机写出事件，不是服务端收到、R2 保存或 D1 提交证据。** 诊断传输与原 fetch 探针不同，不能把它的通过当成官方 App 验收。45 秒是工具诊断等待，不是产品接受标准。

## 本轮观测

- 首轮独立连接：小图片约 1.1 秒返回 200；超限和上限减 1 字节请求约 24 秒发生请求错误；等于上限请求 45 秒超时。后三项均未收到响应头。
- 第二轮保留明确网络码：小图片在 TLS 完成前 ECONNRESET；超限、上限减 1 字节请求 45 秒超时；等于上限请求约 24 秒 ECONNRESET。该轮均未收到上传响应头。
- 同期 Wrangler tail 捕获登录 201 和退出 200，未捕获这些上传的执行事件。只持久化方法、路径、时间、状态与 outcome，未保存原始请求头、异常消息或正文。日志未出现不等于请求绝对未执行。

见 [首轮](contracts/p2-upload-transport-first.json)、[第二轮](contracts/p2-upload-transport-second.json)、[执行摘要](contracts/p2-upload-transport-tail.json)。两轮都确认退出临时会话。

## 结论与下一步

存在当前客户端到服务端连接路径不稳定的证据，问题不只出现在大图片。尚不能确定是本机网络、代理链路、Cloudflare 边缘还是其他原因；没有证据将本次超时归因于 Worker 业务代码或 CPU 超限，也不能排除日志采集之外的执行。没有通过降低密码强度、取消内容校验、扩大超时或更改 reset/ACK 来隐藏问题。

公网完整大小边界仍未通过，P2/G1 保持未完成。下一次应在稳定网络或已确认代理路径重跑原混合 HTTP 探针，并执行官方 iOS 混合队列验收。CPU 超预算优化依用户要求继续暂缓。
