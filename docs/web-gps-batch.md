# 旧照片 GPS 批量读取

照片地图右上角提供“批量读取旧照片 GPS”。先选择照片来源和筛选，再打开面板查看待处理数量。支持全部照片（含归档）、照片、收藏、归档或个人相册，沿用文件名、拍摄日期、照片类型、标签及评分筛选。范围覆盖没有位置、尚未显示在地图上的旧照片，不受当前地图窗口限制。

只处理尚未提取过原件资料的有效照片；已提取但没有 GPS 的照片不会反复读取。回收站、隐藏的 Live Photo MOV 和其他账号不进入任务。每次最多 10,000 张，超出时明确提示缩小范围。新上传已提取资料的照片无需重复处理；单张重新读取继续使用照片资料中的“读取原件信息”。

## 进度与重试

点击“开始读取”后，面板显示已处理/总数、剩余数量、读取成功、可定位、无可用定位、跳过和失败数量，以及当前或最近处理的文件。无 GPS、位置被手动清除或坐标无效均属于成功读取后的“无可用定位”，不会报原件失败。

支持暂停、继续和结束任务。进度保存在服务端，重新打开面板、同标签页刷新或重新登录后可以继续当前账号的任务。每账号只保留一项任务；开始新任务会替换已结束的进度和失败记录，已写入的照片资料保留。任务建立时固定照片清单与来源名称，不随地图筛选改变；建立后新增的照片须另开任务。

失败列表逐张显示文件名、具体原因和尝试次数，可重试这张或重试全部失败。成功项目不会重读。失败较多时每次加载 50 项；重试后相应失败重新进入待处理，已处理进度会相应回退。原件缺失或校验不符需先恢复原件，再重试。照片已删除或被其他操作完成读取时跳过。

任务由打开面板的浏览器逐张推进，不是无人值守后台扫描。关闭面板、离开页面或网络中断后不会主动继续发起后续读取；在途请求可能完成，保存的进度仍可恢复。暂停允许当前在途读取完成，结束任务则阻止未提交请求继续保存。请求结果不确定时先停止推进、刷新服务端进度，再由用户继续；不盲目重发刚才的读取。任务停止、完成或关闭后刷新地图位置与数量。

## 照片资料与权限

复用单张资料提取器读取 JPEG、PNG、HEIC 原件，先检查 R2 原件状态。更新原件 EXIF 来源和已提取标记；手动覆盖（包括显式清除位置与零坐标）、描述、拍摄时间/时区/时间来源、标签评分、收藏、归档及相册关系保留。Live Photo 配套 MOV 不参与读取，照片和 MOV 原始字节、摘要及配对标识均不改变。

读取期间发生编辑时，提交前重新读取最新资料并保留手动修改；照片版本持续冲突时列为可重试失败。元数据、单项结果、进度计数及租约在同一事务提交，事务失败完整回滚。已提取资料复用现有官方 EXIF Sync 与导出路径，不增加官方 App API 或地图设置。

每个读写请求校验当前账号和有效会话；写入要求同源，事务内再次检查会话、归属、任务状态及租约。两个标签页不能同时处理同一任务，一次最多一个原件请求，120 秒租约失效后允许继续；旧请求失去租约后不能提交。取消、账号停用或会话撤销后不能保存迟到结果。无效字段返回具体 `errors[].path/message`，不暴露对象键、校验摘要、租约凭据或会话信息。

## 接口与存储

所有接口位于 `/api/immich-cf/web`，需登录，响应 `Cache-Control: no-store`。

| 方法与路径                          | 用途                                                                                                    |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------- |
| GET `/gps-jobs/preview?mapView=...` | 当前来源/筛选的未提取照片数量、图库版本和来源名称；不接受地图窗口参数                                   |
| GET `/gps-jobs`                     | 本账号保存的任务，尚未建立时为 null                                                                     |
| POST `/gps-jobs`                    | `{scope,version}` 固定范围与清单，版本变化时返回 409，须刷新数量                                        |
| GET `/gps-jobs/{id}`                | 任务进度及前 50 项失败；`failureAfter` 继续读取失败列表                                                 |
| POST `/gps-jobs/{id}/step`          | `{}` 读取下一张；取得租约、读取原件、事务保存结果                                                       |
| PATCH `/gps-jobs/{id}`              | `{action,ids?}`；action 可选 pause、resume、cancel、retry；重试可指定 1～1000 个失败 ID，省略则重试全部 |

迁移 `0038_web_gps_jobs.sql` 新增每账号任务、队列和事务守卫。任务最多 10,000 条，计数由状态变更触发器维护；下一项及失败列表使用索引，不为每张重新扫描完整任务。任务属于账号，不绑定建立时的登录会话；后续操作仍须当前有效会话。队列保留删除项目的文件名和结果以供进度查询，开始新任务会级联清除旧清单。

## 验证范围

新增 11 组集成场景：1001 张实际 EXIF 原件顺序处理、暂停续跑、无 GPS/零坐标/手动清除、PNG/HEIC/Live Photo、缺失与损坏原件、单项和整批失败重试、53 项失败分页、并发编辑/标签页、失效租约、删除跳过、会话撤销、取消与事务故障回滚、账号/来源/筛选/版本/同源隔离。完整检查共 327 项通过；冻结的 279 个操作、53 项来源契约保持。

本机 Chromium 44 项断言覆盖桌面 1440×1000、手机宽度 390×900 和平板宽度 820×900：实际读取、进度暂停/重开/刷新恢复、失败原因、单项和全部重试、原件恢复后完成、地图刷新、响应已提交但丢失后的继续、数量预览失败时仍保留进度，以及固定操作区和无横向溢出。真实手机触控与 iPhone Safari 仍需单独验收。dev 部署和公网结果见 [Web dev 记录](web-v1-dev-deployment.md)。
