# P1 非空图库官方参考对比

日期：2026-10-14。冻结官方 Immich v3.3.1，官方 App 不修改；范围为两张合成静态图片，不代表完整相册能力。

## 复现与测试数据

沿用 [隔离参考环境](../infra/reference/README.md)：`pnpm reference:up` 后运行 `pnpm reference:compare`，完成后 `pnpm reference:down`。每次创建合成普通用户和全新本地 D1/R2，与 dev 数据隔离。参考卷保留，因此历史用户数量影响 UserV1 数量，不能将它作为固定数量断言。

共享用例 `scripts/reference-nonempty.mjs` 同时用于实际双端比较和常规本地回归。上传仓库自带 320×240 PNG/JPEG，各带一项 mobile-app 元数据，PNG 为收藏。日期、文件名和元数据使用合成值；报告只保留类型、夹具名和测试结果，不保存令牌、实际资产 ID、账号、原图或访问 URL。

## 硬断言

- 两张图片分别首次上传 201、重复上传 200，重复返回原资产 ID。
- 原图 200 且字节与夹具完全一致；预览等待异步生成（最多 60 次，间隔一秒），必须 200、非空、image MIME 和 PNG/JPEG 签名。未登录原图请求必须 401。
- Sync 包含且只包含本次两张资产；逐张核对 SHA-1、图片类型、名称、尺寸、日期、收藏、timeline 和 mobile-app 元数据关联。
- 全部 AssetV2 先于 AssetMetadataV1。未 ACK 重拉仍包含两张图片；只 ACK 第一张资产后，其它资产和两项元数据仍可拉取。
- 完整 ACK 后仅 Complete；显式 reset 直接返回非空快照，图片 owner 的 UserV1 在图片之前，ACK 后重新回到仅 Complete。

## 发现与修正

实际官方输出先发送全部 AssetV2，再发送全部 AssetMetadataV1。此前 immich-cf 按图片交错发送资产与元数据。本轮改为按家族分组输出；各家族内部仍按资产 seq 排序，不改变游标格式、reset epoch 或 ACK 事务隔离，也无需数据库迁移。共享断言和本地回归会阻止交错顺序重新出现。

## 保留的差异与验收边界

| 项目             | 官方参考结果                          | immich-cf / 决策                                                 |
| ---------------- | ------------------------------------- | ---------------------------------------------------------------- |
| 预览             | 异步生成 JPEG 衍生图，字节不同于原图  | 有界小图片沿用原图预览；验证能读取，不要求衍生图字节相同         |
| thumbhash        | 处理后为字符串                        | null；合法可空字段，暂不生成                                     |
| UserV1           | 可重放参考环境的其它可见用户          | 当前用户隐私范围；已存在的能力差异                               |
| ACK              | 官方游标格式                          | 保留隔离 epoch，不要求字面字符串相等                             |
| 上传后的用户事件 | 官方同时更新用户状态；可能包含 UserV1 | 本实现通过 AuthUserV2 的配额修订同步；不要求所有用户事件数量一致 |

本轮使用无 EXIF 旋转的两张小图片，不覆盖 HEIC、视频、Live Photo、大文件、真实相机时区、编辑/删除/相册/共享、批量并发图库、所有 Sync 家族、后台备份、Free CPU 或官方 App 新一轮真机验收。预览签名检查不是完整图像解码或像素比较。参考服务端机器学习服务未启用，不能将上传成功视为机器学习验收。

既有 16 项身份/空图库字段投影保留独立结果；非空图库使用行为与关键值硬断言，不能把两者汇总为“全部字段完全兼容”。
