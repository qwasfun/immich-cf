# P3：R2 摘要副本安全清理与崩溃恢复（本机）

## 范围与保护边界

`cleanStorageCopy` 是内部原语，每次仅处理一个明确指定的当前账号摘要副本键：`owner/uuid/verified-sha1-40位小写十六进制`。没有自动枚举、定时任务或生产维护 API；测试入口仅存在于 fault-worker。本轮不部署、不迁移远程数据库、不访问真实 R2。

原图 `/original`、未知格式键、跨账号键直接拒绝。即使没有引用也不清理原图。即使对象缺失、损坏、预约很旧，也不据此删除任何引用或预约。数据库认领检查跨账号的全部已知引用：

- assets.object_key、assets.integrity_source_key；
- retired_assets.object_key、retired_assets.integrity_source_key；
- upload_intents.object_key；
- 新增 integrity_copy_intents.object_key（升级副本写入预约）。

保留退役原图、历史源和全部预约。当前策略故意允许存储泄漏：曾预约但未发布的副本也不会回收。只读 storageAudit 的旧分页模型没有包括新增摘要预约，不应将其结果直接作为清理授权；最终授权由数据库触发器检查上述完整集合。

## 并发与恢复协议

迁移 0017 增加 integrity_copy_intents、r2_cleanup_claims 和引用隔离触发器。历史摘要升级在任何副本 HEAD/PUT 之前持久预约；失败、发布成功均保留预约。原图读取、校验算法、大小限制、密码与 Sync 协议不变。

清理先在 D1 原子 batch 中认领，提交时检查当前有效会话，并由 BEFORE INSERT 触发器核对全局引用。引用先提交则拒绝认领；认领先提交则所有引用表的 INSERT/相关 UPDATE 均拒绝使用此键。认领键及 owner 不可修改，认领不可删除，不使用会过期的租约。

只有认领成功才调用幂等 R2 delete，随后 HEAD 确认不存在，最后记录 done。R2 故障或数据库故障不释放认领；无响应或进程退出后使用同一账号、同一 key 重新执行。认领和最后一次会话核验完成后的操作允许完成，即使随后会话被撤销；恢复请求仍需有效会话。done 重放也执行删除与确认，处理旧进程晚到 PUT 再产生的无引用字节；不会解除隔离允许重新发布。

如果某个历史升级的确定性副本键已被清理认领，升级改用新的随机私有代际键，先预约再写入，保留原图及旧清理标记。仅对此明确冲突切换一次，其他错误仍失败，不做无限重试。

认领永久隔离是安全性的前提，不能手工删除标记后重用键。D1 和 R2 不存在跨存储事务，因此 done 是当次观察，不是禁止外部写入 R2 的物理锁。所有应用发布路径必须遵守引用触发器；直接管理台写入可能重新制造孤儿。后续新增引用表必须先纳入同一协议。

## 运行与发布边界

本机测试用随机隔离 D1/R2 和合成对象，不读取私人照片。需要本机迁移 0017；不要连接尚未迁移的远程 dev。发布前必须停止旧版不预约的升级写入者，再运行迁移和兼容版本；旧写入者的发布会被隔离拒绝，但可能留下晚到孤儿。当前没有自动安全发现候选或线上运维 CLI，不能宣布完整自动 GC 或 P3 全部完成。

## 回归矩阵

| 场景                                                        | 要求                                   |
| ----------------------------------------------------------- | -------------------------------------- |
| 无引用摘要副本 / 缺失对象                                   | 删除并确认，重复执行幂等               |
| 活动原图、历史源、退役原图/源、上传/摘要预约                | 拒绝认领，无 R2 删除                   |
| 原图格式、未知格式、跨账号键                                | 字段错误，保留对象                     |
| 认领前新增引用、会话撤销                                    | 提交检查失败，不删除                   |
| 认领后 INSERT/UPDATE 引用                                   | 所有引用表拒绝，永久隔离               |
| 认领提交后响应丢失、删除前/后故障、HEAD 失败、done 写入失败 | 保留 claimed；同 key 重试完成          |
| done 后响应丢失、晚到无引用写入                             | 重放确认并清理，隔离保留               |
| 已认领历史副本重新升级                                      | 新代际先预约，原图与旧隔离保留         |
| 非空旧 schema 前向迁移                                      | 原资产、源、预约、检查点与单调时钟不变 |

完整测试结果与提交一起记录。本机回归不替代官方 iOS 真机、远程平台成本或 P3 的 1,000 真实资产验收；CPU 超预算继续暂缓。
