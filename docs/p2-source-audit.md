# P2 历史原图引用只读对账

将迁移 0013 保存的 `assets.integrity_source_key` 纳入已有 `POST /api/immich-cf/storage-audit`。本轮只扩展读取与验证，不执行对象补写、删除、预约清理或同步状态变更，不新增数据库迁移。

## 引用与分页契约

- `asset`：当前 `assets.object_key`，保留原生摘要要求标记。
- `intent`：`upload_intents.object_key`，仍区分 pending 与 published-checksum。
- `source`：非空 `assets.integrity_source_key`，使用所属资产 ID，返回 relation=retained-original、publishedId=所属资产 ID、checksumRequired=false。false 表示历史原图未被强制升级为原生摘要，绝不降低当前资产的校验要求。

游标按 `asset:ID`、`intent:ID`、`source:ID` 排序，after 接受并验证 source 游标；固定每页最多 20 条引用、最多 20 次 R2 HEAD，SQL 多取一条判断是否存在后续页。引用从同一账户内的资产与预约读取，不扫描 R2 全桶，不返回路径、文件名或摘要。

计数是引用数，不是独立对象数。同一历史对象可能同时被 source 与 intent 引用，仍分开报告，两条都必须保留；不能把同一个资产 ID 的 asset/source 条目误认为重复。探针按 kind+id 判断重复引用，报告保留每页条目数并过滤 ID/存储路径。

D1 查询、R2 HEAD 和分页之间仍非一致性快照。并发升级可能在游标经过后增加源引用，需从第一页重新检查；观察结果不能用作自动清理授权。

## 状态与恢复边界

source 与资产采用同样的大小和可用原生摘要检查：missing、size-mismatch、checksum-mismatch、checksum-unavailable、unavailable、verified。没有原生 SHA-1 的旧原图即使大小正确，也只报 checksum-unavailable。HEAD 不能发现无原生摘要对象的等长内容变更；真正使用源恢复副本时，现有升级接口仍完整读取并计算 SHA-1，与 D1 比较，不匹配则拒绝。存储不可用绝不能被当作缺失或摘要通过。

对账只观察状态：历史源异常但当前校验副本正常时，当前预览仍可用；对账不自动修复或切换原图。当前副本缺失/摘要错误而历史源有效时，可通过既有 upgrade-integrity 的预检/apply 恢复，再重新对账；源与副本均异常时拒绝恢复，保留严格摘要标记、原图引用及预约，不回退成不检查摘要的读取模式。

pageObjectsVerified 仍只表示本页非空且每条引用都有原生摘要证明。来源未升级、预约未验证都可能令它为 false，这不等于当前校验副本损坏，也不能据此判定全库健康。
