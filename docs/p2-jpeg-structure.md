# P2 JPEG 扫描结构与后置元数据检查

日期：2026-10-16，对应 P2-01 内容校验。混合备份真机结果未收到，仍为待验证；CPU 超预算继续暂缓。

原实现识别到第一个 SOS 就停止遍历。这样文件末尾即使存在 EOI，也无法排除中间段长度损坏、提前 EOI 后拼接其他图像，以及 SOS 之后的未检查 APP1 元数据。

本轮按标记/扫描数据状态继续遍历到唯一的末尾 EOI：处理 FF00 转义、RST0–RST7 重启标记和多扫描；检查 SOF0/SOF2 与 SOS 的长度及顺序；拒绝越界段、内部 SOI、提前结束后的额外数据。所有遇到的 APP1 继续走已有 EXIF/Live Photo/XMP 规则，后置配对标签不能因位置不同绕过。支持范围仍为既有 8 位基线/渐进式 JPEG；不支持的结构保守拒绝。

依据 [ITU-T T.81](https://www.w3.org/Graphics/JPEG/itu-t81.pdf) 的标记和扫描结构。**这不是完整 JPEG 解码器**：没有验证 Huffman/量化表内容、重启间隔正确性或像素能否全部解码，不能将结构通过视为所有损坏文件都能检出。PNG、4 MiB/400 万像素限制、认证与 reset/ACK 不变。历史尺寸修复共用图片检查器，损坏结构会被拒绝，不会自动删除历史资产。

## 回归与样本来源

新增样本由 Pillow 在本机从纯色/数学图案生成：32×24 渐进式 JPEG、64×64 带重启标记和 FF00 字节转义的 JPEG，均由 Pillow 实际解码成功；不是用户照片，也不计为真实图库 100 张验收。

真实 Worker/D1/R2 回归覆盖基线、渐进式、重启/转义、后置普通 XMP、后置 Live Photo/未知 XMP 拒绝、段长度越界、第二个 SOI、图片拼接、错误 SOS 长度和缺失 EOI。成功项验证去重、原图字节及 Sync/ACK；失败项验证具体 assetData 错误，无新增资产/上传意图/R2 孤儿。原有 XMP 真样本和 reset/ACK 并发用例继续运行。

公网脚本 node scripts/jpeg-structure-probe.mjs 使用固定合成图片，可去重，保留正常样本。先用错误校验和探测后置 Live Photo 拒绝，避免发布传播期间旧代码保存就绪探针。无新增迁移，test/生产不发布。
