## 三份迁移

- **0014_asset_history.sql**：账户版本不再取现存资产 MAX(seq)，避免删除最高编号后版本倒退。新增资产删除日志、退役引用；变更触发器覆盖当前同步业务字段。资产 ID/owner 不可变，已退役 ID 不可重新插入；同 checksum 重新上传可获新 ID，旧删除事件与保留源仍在。
- **0015_history_retention.sql**：清理任务及历史保留水位；资产与 metadata 两个会话基线分开，避免只重建一种家族就掩盖另一种家族缺失。stream/reset-snapshot 在登记投递的原子 guard 中重查保留水位，压缩期间的旧流返回 409，不产生伪 Complete。
- **0016_asset_metadata_history.sql**：当前资产 metadata 键移除与原业务更新原子记录；同键重新加入时不投递会删除当前值的旧删除记录。事件载荷按冻结 OpenAPI 的 SyncAssetMetadataDeleteV1。

迁移保留已有资产 ID、原图路径、历史源引用、预约、同步检查点与时钟；非空 0013 前向迁移另有回归。原有 4 MiB、6400 万像素/单边 16384、20 张逻辑额度、Live Photo 防护、bcrypt cost 12、会话鉴权不降低。

## 删除原语与私有读取

`retireAsset` 是内部业务原语，提交时在 D1 中重新检查会话有效期、禁用与所有权；会话检查同时取提交时数据库时钟，不能靠早先鉴权结果保留过期权限。重试返回已退役状态，不重复产生删除序号。删除与 tombstone/原图引用/账户版本一起提交或一起回滚。

删除后旧资产详情、原图和预览均 404，R2 原图仍保留；可通过只读对账观察 retained-deleted-original / retained-deleted-source。历史源缺少原生摘要时仍标为未验证，不把 HEAD 成功当作内容完整。

**生产路由没有接入退役或清理 API。** `/api/assets/:id DELETE` 仍拒绝，测试调用仅存在于 tests/fixtures/fault-worker.ts 的 /__test 路径；src/index.ts 生产构建不包含这些测试入口。不将内部原语交付说成已实现 App 删除按钮、回收站或永久删除。

## 历史压缩与恢复语义

`compactHistory` 内部原语按 owner 与持久 jobId 执行，cutoff 固定为至少 30 天前的规范 UTC ISO 时间，每批 1～100 条。游标选择、删除记录、保留水位与任务进度在 D1 原子 batch 中提交；每个变更都检查任务原游标和当前会话。并发推进或撤销会话不会覆盖新进度。响应丢失/进程中断后继续用同一 jobId/cutoff 重试，完成任务重放为 0 条处理；不同账号不能复用任务操作他人数据。

压缩不接收 R2 bucket，无法删除对象；retired_assets 和原图/源引用、未完成预约均保留。仅删除已超保留期的同步日志。客户端删除 ACK 或家族重建基线落后于保留水位，即使最近 Complete 很新，也会得到 SyncResetV1，确认后全量重建；新会话、显式 reset 和按家族重建后不会无限循环 reset。

故障回归覆盖：floor 写入失败整批回滚；D1 提交后响应丢失；旧流已读取但未登记时发生压缩；会话撤销；任务重放；资产与 metadata 家族独立恢复。D1 历史压缩不回收 R2；新增的本机摘要副本清理原语见 [R2 安全清理](p3-r2-cleanup.md)，自动 GC 仍未开放。

## 查询与规模证据

资产、非空 metadata、资产删除和 metadata 删除分别按 owner/同步序号索引范围读取，先读取请求高水位再限制各家族上界；后续写入进入下一轮。资产与元数据家族顺序保留，单调序号不依赖客户端时间或同毫秒时间戳。

本机 D1/Miniflare 中手工种入 **10,000 条合成删除元数据**，不提升 20 张上传限制，不伪造真实原图。首次同步完整返回 10,000 个不同 ID、确定顺序、Complete；以 200 个 ACK 一批确认，随后空增量。相同索引查询本机 meta.rows_read：首次 **10001**，空增量 **1**。EXPLAIN 使用 asset_tombstones_owner_seq。此数据只代表本机该查询，不代表完整请求总成本、平台计费或所有同步家族 10,000 项均已验收。

## 本机运行与后续步骤

新代码依赖本机 0014～0018 schema。只在隔离/本机数据库运行：

```powershell

pnpm dev:local
pnpm check
```

不要用默认 pnpm dev 连接尚未迁移的远程 dev 数据库。当前公网保持上轮 P2 版本；没有部署或迁移 test/生产。

P3 整体退出仍缺：1,000 个合法真实资产与设备/服务端按 ID/状态对账、官方 App 的删除/关系/离线重建验证；R2 自动候选发现与线上运维接入、后续相册关系模型、实际平台查询成本。P2/G1 未通过与 CPU 暂缓状态继续保留。后续分步完善这些项目，不能宣布 P3 全部完成。
